## Результаты работы

### Этап 1. Выбрать и подготовить источники данных
В качестве корпуса документов были взяты дополнительные материалы к курсу "Визуальные формы мышления". Всего в базе 5 документов:

1. Малви Л. «Визуальное удовольствие и нарративный кинематограф» — 18 стр.
2. Нерони Х. «Наслаждение по Джейн Кэмпион» — 16 стр.
3. Кэрролл Н. «Notes on the Sight Gag» (из «Theorizing the Moving Image») — 12 стр.
4. Вертов Д. «Мы. Вариант манифеста» — 8 стр.
5. Барт Р. «Риторика образа» — 22 стр.

Суммарно: 76 страниц

По этим документам были подготовлены репрезентативных вопросов с эталонными ответами и ссылками. Они размещены в файле `questions.md` с единой структурой.

### Этап 2. Спарсить источники в Markdown

Для перевода PDF в Markdown использую PyMuPDF4LLM и PyMuPDF (+ Tesseract OCR). Каждая страница сохраняется в отдельный .md-файл с метаданными: источник, номер страницы и способ извлечения.

Далее на этапе проверки результатов конвертации было принято решение сделать в конфиге выбор для каждого документа, подключать OCR или нет. Это сделано, потому что у исходных PDF разное качество текстового слоя. Один способ извлечения для всех документов давал неудовлетворительный результат.

| Документ | Что обнаружилось | Выбранный режим |
|---|---|---|
| **Вертов — «Мы. Вариант манифеста»** | Без OCR основной текст отсутствовал: извлекались преимущественно служебные строки, URL и номера страниц. С OCR появился содержательный текст, но на странице 6 остался большой фрагмент шума | С OCR |
| **Малви — «Визуальное удовольствие и нарративный кинематограф»** | Без OCR встречались сильно испорченные последовательности символов. После OCR основной текст стал читаемым | С OCR |
| **Барт — «Риторика образа»** | Без OCR текст извлекался, но встречались разрывы слов | Без OCR |
| **Кэрролл — «Notes on the Sight Gag»** | Без OCR текст извлекался; были подозрения на перемешивание колонок, требующие сверки с PDF | Без OCR |
| **Нерони — «Наслаждение по Джейн Кэмпион»** | В предыдущей проверке существенных проблем извлечения не отмечено | Без OCR |

То есть для последних трех документов результат с OCR давал примерно такой же результат.

После конвертации PDF в Markdown добавлен отдельный этап минимальной нормализации: удаление мягких переносов, замена неразрывных пробелов обычными и очистка концов строк с сохранением структуры Markdown. Чтобы не «переобучать» подготовку данных под выбранную базу документов, правила для отдельных авторов, страниц и ошибок распознавания не добавлялись. Такой подход применим к новым документам, однако не устраняет OCR-шум, нарушения порядка чтения колонок и другие ошибки извлечения текста.

### Этапе 3. Разбить на чанки и построить эмбеддинги (sparse/dense)

Для разбиения Markdown-документов на чанки реализовано два сплиттера из langchain-text-splitters (`MarkdownHeaderTextSplitter` и `RecursiveCharacterTextSplitter`), объединённые в гибридную схему.

Для построения dense-эмбеддингов использовалась BGE-M3 (https://huggingface.co/BAAI/bge-m3), размерность 1024, формат float32. 

Все параметры регулируются через config.yaml.

### Этап 4. Развернуть векторное хранилище и загрузить индекс

Для построения индекса использовалась библиотека FAISS.
В скрипте реализована возможность строить три индекса:

* Flat
* HNSW
* HNSW-PQ

Для дальнейших экспериментов был выбран HNSW без квантизации.
Корпус содержит лишь несколько сотен векторов: этого мало для качественного обучения PQ, а экономия памяти при таком объёме несущественна. Параметры HNSW во всех экспериментах зафиксированы, чтобы сравнивать влияние разбиения на чанки.

## Выводы

Ошибки в работе пайплайна могут возникать на каждом из его этапов ().

### Выводы по экспериментам

- При переходе hybrid 400/60 → 700/100 меняются одновременно размер и overlap.
  Recall@5 растёт с 0,7667 до 0,8000, но средний контекст увеличивается
  примерно на 54%. MRR@5 немного снижается.
- При одинаковых 700/100 recursive даёт ту же полноту, что и hybrid, и лучший
  MRR: 0,6078 против 0,5744 при k=5. Обработка заголовков hybrid на этом
  корпусе не дала преимущества по выбранным метрикам.
- Для следующего этапа выбран **recursive 700/100** как вариант с лучшим MRR
  и максимальной измеренной полнотой при k=10. Рабочий конфиг пока не переключён.
  При ограниченном бюджете контекста стоит рассматривать hybrid 400/60:
  его top-10 занимает около 3285 токенов при Recall=0,9000.
- У recursive переход k=5 → 10 повышает Recall с 0,8000 до 0,9667,
  увеличивая контекст с 2688 до 4988 токенов.

Разбор конкретных вопросов

- q08: эталонная страница появляется на ранге 6 у hybrid 400/60, 8 у
  hybrid 700/100 и 7 у recursive 700/100; top-5 её не содержит.
- q10: уменьшение чанков поднимает эталонную страницу Кэрролла с ранга 9
  на ранг 3. Это не подтверждает исправление порядка колонок в исходном тексте.
- q11: у hybrid 400/60 эталонной страницы нет даже в top-10;
  у обоих вариантов 700/100 она на третьем месте.
- q12: hybrid 400/60 находит обе эталонные страницы уже в top-5;
  варианты 700/100 находят вторую страницу только на ранге 10.
- q15: во всех вариантах top-10 содержит страницу Нерони, но не содержит
  эталонную страницу 16 Малви; Recall вопроса остаётся 0,5.
